# 统一生成架构

画布和逐镜生产共享持久化任务、素材版本、执行规则与结果校验；保留各自的输入解析和编排方式。

## 模块边界

| 模块                              | 职责                                                                                         |
| --------------------------------- | -------------------------------------------------------------------------------------------- |
| `lib/server/generation-ledger.ts` | 任务读写、不可变素材版本、版本号分配、旧数据迁移；只接受 SQLite 连接，不启动事务、不调用模型 |
| `lib/generation/lifecycle.ts`     | 可执行性、租约认领、提交中断保护、结果所有权和轮询重试；无数据库或网络依赖                   |
| `lib/generation/results.ts`       | 输入版本、用户选择与画布结果应用校验；无副作用，可在浏览器与服务端复用                       |
| `lib/server/task-governance.ts`   | 基于统一任务表的全局配额、项目删除屏障、历史恢复保护                                         |
| `lib/server/canvas-jobs.ts`       | 画布输入快照、上下文依赖、生成服务调用和兼容任务 DTO                                         |
| `lib/server/production.ts`        | 镜头生成计划、请求幂等、图片前置依赖、素材选择                                               |
| `lib/server/production-store.ts`  | 逐镜接口适配：从共享账本组装原有 ProductionState；事务提交任务、素材和选择元数据             |
| `lib/server/generation-worker.ts` | 镜头依赖解析、Provider 适配和完成结果提交                                                    |
| `lib/production/apply.ts`         | 校验选中版本与分镜一致，将镜头素材组装为剧情片段                                             |

Provider 调用、文件下载不占用数据库事务。任务认领、外部任务 ID 保存、完成状态与素材版本提交分别在短事务内完成。提交中断且未保存外部任务 ID 时标记失败，避免自动重复计费；已有外部任务 ID 的错误只重试轮询。

## 数据归属

- `generation_tasks`：两种流程唯一的任务数据源，通过 `scope` 与 `target_id` 区分节点和镜头。状态索引列从 JSON 文档生成，避免双写不一致。任务完整快照保留在文档中，刷新和 Worker 重启不丢失上下文。
- `generated_versions`：两种流程唯一的生成素材版本库。每个任务至多一个结果版本；每个项目、流程、目标、素材类型的版本号唯一。既有版本禁止覆盖。
- `production_states`：只保存逐镜请求幂等键、选中版本、选择修订号和接口修订号，不再复制任务和素材数组。接口响应仍提供 jobs/assets 以兼容现有 UI。
- 项目文档：保存实际应用的 URL、片段与版本引用。它与生产结果库有明确边界，生成完成并不等于覆盖当前作品。

画布完成任务时立即登记素材版本，浏览器未打开也可在素材库找到结果。浏览器应用结果需要输入指纹、当前 URL 和当前选择版本均未变化；否则仅保留历史版本。逐镜生成只在选择修订号未变化时自动选择结果，应用到剧情前再次校验分镜版本。不同领域的具体应用逻辑仍由各自适配模块负责。

## 迁移与运行

数据库连接对外提供前，在同一事务内迁移旧 `canvas_jobs` 以及 `production_states.jobs/assets`，保留原任务 ID、外部请求 ID、素材 ID、选择与修订号，媒体文件无需移动。迁移失败整体回滚，成功后记录 `generation-ledger-v1` 并移除旧表及重复数组。

升级时应先停止旧 Web/Worker，再部署同一版本的 Web/Worker。旧二进制仍使用旧表结构，不能与新版本混跑。迁移后回退旧应用需要恢复升级前的数据库备份。

## 验证

`npm test` 覆盖两套流程及新增账本迁移、不可变版本事务回滚、浏览器应用前素材可见、租约接管与结果保护。`npm run test:production` 使用隔离数据库和模拟 Provider，验证刷新、Worker 重启、单镜重试、历史版本选择及匿名浏览器播放，不调用付费模型。

## 创作输入与文本生成

- `lib/story/creation-brief.ts` 是首页、编辑器、服务端共同使用的配置契约。类型与题材分开；“自动”表示由创意推断题材。配置与项目一起保存，旧项目使用兼容默认值。
- `lib/ai/story-generation.ts` 负责一次流式模型调用与故事校验；首页和编辑器共用 `/api/ai/script`，不再通过工具循环反复重述大纲。旧 Agent 工具也复用该生成实现。
- `lib/ai/text-generation.ts` 负责 SSE 错误处理、上下文预算、默认 8000 输出 token 和 120 秒单次超时。`TEXT_CONTEXT_WINDOW` 可覆盖供应商默认上下文窗口；密钥只在服务端读取。
- `useCreationRequest` 只负责请求、取消和读取完整响应，不写项目。领域校验成功后，表单保存候选草稿；应用模块再替换画布。候选剧本同时保存生成时的 Brief，避免后续修改设置导致来源混淆。
- `output-validation` 校验场景引用、可达性、循环和线性/决策点约束；`shot-plan` 按每条观看路线校验目标时长（±25%），不把互斥分支时长相加。
- 参考图通过共用选择器附着到当前输入，最多 4 张。文本阶段使用用户填写的参考说明，不声称文本模型看过图片；原图保留为独立画布素材，后续可手动连接到生成节点。此流程没有自动图片理解。
- 短剧和剧本分镜使用线性规划、自动后继与单个结局；互动剧保留分支步骤。角色/场景入口创建带对应素材类型及生成说明的独立图片节点。
